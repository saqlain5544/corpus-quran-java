# Quran Reader — Implementation Reference

> Complete annotated tour of the Go + vanilla JS/CSS/HTML Quran Reader.
> For high-level design (architecture, routes, UI tokens), see `docs/pen-and-paper/`.
> For research findings (data schemas, MASAQ quirks, performance), see `docs/research/`.

## 1. What this is

A self-contained web app that lets you read the Quran (Tanzil Uthmani),
hover any word for its morphology, click for a deeper modal, and search
by Arabic word, English gloss, or root. Written entirely in Go
(stdlib only) + vanilla JS + vanilla CSS + vanilla HTML — no
frontend framework, no npm, no bundler, no external fonts (one WOFF2
file shipped in-repo).

The app respects the constraints set in `agents.md`:

| Constraint | Status |
|---|---|
| Trusted data only (`quran-uthmani.xml`, `MASAQ.csv`, `hafs.woff2`) | ✅ plus AI-generated meanings (clearly labeled) |
| Memory under 80 MB heap | ✅ ~78 MB (RSS ~115 MB with Go runtime) |
| No external frontend frameworks | ✅ vanilla JS only |
| Editorial UI, typography-first, 12-col grid with 2-col gutters | ✅ |
| Keyboard-accessible, `prefers-reduced-motion` respected | ✅ |
| AI-generated root meanings clearly labeled | ✅ on `/root/{root}` page |

## 2. Quick start

```sh
# One-time preprocessing: raw data → optimized gob files.
go run ./pipeline/cmd/build \
  -data   ./data \
  -out    ./data/processed \
  -report ./docs/data-verification/build-report.txt

# Run the server.
go build -o ./bin/quranreader ./backend
./bin/quranreader -addr :8080 -data ./data/processed
# → open http://localhost:8080/
```

## 4. Data pipeline (preprocess once, run many times)

The pipeline turns the raw data files into compact gob-encoded
files that the server loads at startup. Files referenced:
[`pipeline/build.go`](pipeline/build.go).

### 4.1 Flow

```
data/quran/quran-uthmani.xml
        │
        │  parseQuran     [pipeline/quran_parse.go:parseQuran]
        ▼
types.Quran
   Surahs map[int]*Surah
       │
       │  tokenize        [pipeline/quran_parse.go:tokenize]
       ▼
   Surah.Ayahs[N].Tokens []types.Token
        │  Kind: "word" | "mark"
        │  For word: Value (Arabic without trailing marks), WordNo (1-based within ayah), Marks (trailing pause/iqlab/sajdah chars)
        │  For mark:  Value (the mark character)
        │
        │  emitGob         [pipeline/build.go:emitGob]
        ▼
data/processed/quran.gob  (~3.5 MB)

data/morphology/MASAQ.csv
        │
        │  parseMasaq     [pipeline/masaq_parse.go:parseMasaq]
        ▼
types.MasaqIndex.ByWord[loc.Key(surah,ayah,word)] = []MasaqSegment
        │  gob.Encode
        ▼
data/processed/masaq_index.gob  (~19 MB)

data/morphology/corpus-roots.json
data/morphology/meanings-roots-ai.jsonl
        │
        │  parseRoots     [pipeline/roots_parse.go:parseRoots]
        │  joins the two files on buckwalter root key
        ▼
types.RootsIndex
   ByRoot[buckwalter] *RootEntry
   ByLoc[loc.Key(s,a,w)] buckwalter
   ByArabic[letters] buckwalter
        │  gob.Encode
        ▼
data/processed/roots.gob  (~1.6 MB)
```

### 4.2 Parallelism

`Build()` in [`pipeline/build.go`](pipeline/build.go) reads all
four raw files concurrently in goroutines, then parses the
in-memory byte slices sequentially. The wall-clock gain is most
noticeable on cold caches (the four files are 1.5 + 18 + 2 + 1 ≈
22 MB total).

### 4.3 Tokenization rules (the only non-trivial parsing logic)

[`pipeline/quran_parse.go`](pipeline/quran_parse.go):

- **Word tokenization** (`tokenize`): split on whitespace, peel trailing
  marks off the end of each token via `splitMark`. Trailing marks stay
  in the word's `Marks` array; only standalone marks (whitespace-
  delimited with no word body, e.g., the rub' `۞` at the start of an
  ayah) become separate `mark` tokens.

- **Trailing marks set** (`tokenTrailingMarks`): characters in the
  U+06D6..U+06ED range that we treat as marks to peel off:
  `ۖ ۗ ۘ ۙ ۚ ۛ` (pause marks), `ۜ` (sakta), `۞` (rub'), `ۢ ۭ`
  (iqlab high/low meem), `۩` (sajdah). All other Arabic-Extended
  characters (e.g., `۟ ۠ ۥ ۦ ۧ ۨ` and the stop marks `۪ ۫ ۬`) are
  diacritics that belong to the letters themselves — they are NOT
  trailing marks.

- **Bismillah rules** (`parseQuran`):
  - Surah 1 verse 1 IS the Bismillah (counted as verse 1, no separate bismillah attr).
  - Surah 9 has no Bismillah.
  - For all other surahs, if the `bismillah` attribute is set, store it;
    if aya 1's text equals the canonical Bismillah, skip that aya (so it
    doesn't double as verse 1).

### 4.4 Verification

`Build()` runs checks after parsing and reports them in
`docs/data-verification/build-report.txt`:

| Check | Expected | Actual |
|---|---|---|
| surah count | 114 | 114 ✓ |
| ayah count | 6236 | 6236 ✓ |
| masaq word count | ≥ 77000 | 77411 ✓ |
| root count | > 1600 | 1642 ✓ |
| strict positional MASAQ misses | (informational) | 23 |

The 23 misses are documented known divergences where MASAQ merges a
conjunction particle with the following word (e.g., `وَ+X` → `وX`).
The UI shows "No morphological data" for those positions rather than
guessing.

## 5. Server runtime

### 5.1 Startup

[`backend/main.go`](backend/main.go):

1. Parse flags: `-addr` (HTTP listen address), `-data` (processed dir).
2. Set runtime tuning:
   - `GOMEMLIMIT=96 MiB` (soft cap on heap; heap already stays under
     this naturally)
   - `GOGC=200` (less aggressive GC for our stable working set)
   - `GOMAXPROCS=4` (cap on parallelism; this app is I/O-bound, not
     compute-bound)
3. Read all four processed files in parallel via
   [`backend/internal/data/load.go:LoadAll`](backend/internal/data/load.go).
4. Build the server with
   [`backend/internal/server/server.go:New`](backend/internal/server/server.go).
5. Start `http.ListenAndServe`.

### 5.2 Request handling

[`backend/internal/server/server.go`](backend/internal/server/server.go): `Handler()` builds the routing tree:

| Path pattern | Handler |
|---|---|
| `GET /` | `handleHomepage` |
| `GET /surah/{id}` and `/surah/{id}/{verse}` | `handleSurah` |
| `GET /search` | `handleSearch` |
| `GET /roots` | `handleRootsList` |
| `GET /root/{root}` | `handleRootDetail` |
| `GET /about` | `handleAbout` |
| `GET /api/word?s=&a=&w=` | `handleAPIWord` |
| `GET /api/search?q=&type=` | `handleAPISearch` |
| `GET /api/roots?page=&sort=` | `handleAPIRoots` |
| `GET /api/root/{root}/occurrences` | `handleAPIRootOccurrences` |
| `GET /api/health` | `handleHealth` |
| `GET /static/...` | `http.FileServerFS` over the embedded `static/` |
| `GET /fonts/...` | `http.FileServerFS` over the embedded `fonts/` |

Middleware chain (outer→inner): `recovery` → `logging` → mux.

### 5.3 The `/api/word` response shape

`handleAPIWord` in [`backend/internal/server/server.go`](backend/internal/server/server.go) returns:

```json
{
  "surah": 1,
  "ayah":  1,
  "word":  2,
  "word_text": "ٱللَّهِ",
  "lemma":    "الله",      // proper noun → full form; otherwise prefix + stem
  "gloss":    "(of)-allah", // stem segment's gloss, deduplicated
  "pos":      "N",          // from root POS; fallback to MorphTag
  "function": "Genitive construct (genitive)",
  "segments": [ /* full MASAQ segment rows */ ],
  "root": {
    "buckwalter": "Alh",
    "arabic":     "أَلِه",
    "letters":    "أ ل ه",  // space-separated consonants
    "pos":        "N",
    "meaning_en": "…",
    "meaning_ar": "…",
    "link":       "/root/Alh"
  }
}
```

Helper functions used:
- `computeLemma(segs)` — proper noun → full word; otherwise prefix + stem.
- `combineGlosses(segs)` — prefer the Stem segment's gloss.
- `grammaticalFunction(segs)` — friendlyRole (SyntacticRole map) → fallback to friendlyMorphTag (CV/IV/PV).

### 6.3 Template architecture

Each page template overrides the layout's `{{define "content"}}` block. To prevent Go's html/template `{{block}}` gotcha (where the last-parsed "content" template clobbers all others), each page is parsed into its own `*template.Template` in [`loadTemplates`](backend/internal/server/templates.go):

```go
for _, name := range pageFiles {
    t := template.New("").Funcs(funcMap())
    t.New("layout").Parse(layoutBytes)
    for name, b := range partialsBytes {
        t.New(name).Parse(b)
    }
    t.New(pageName).Parse(pageBytes)
    out[pageName] = t
}
```

The result: each page's "content" symbol resolves only to its own
definition. ExecuteTemplate renders the page → which calls
{{template "layout" .}} → which has `{{block "content" .}}` → which
fills in the page-specific content.

The surah page is the most interesting:

```html
{{define "surah.tmpl"}}{{template "layout" .}}{{end}}
{{define "content"}}
<div class="page-surah" data-surah="{{.Surah.Number}}">
  <header class="surah-header">…title, search, font/line controls, prev/next…</header>
  {{if .Surah.Bismillah}}<p class="bismillah" lang="ar" dir="rtl">{{.Surah.Bismillah}}</p>{{end}}
  <article class="quran" lang="ar" dir="rtl">
    {{range $an, $ay := .Surah.Ayahs}}…render ayah, with .ayah-focus when VerseAnchor matches…{{end}}
  </article>
</div>
{{end}}
```

The ayah loop uses Go template `{{- ... -}}` trim markers to keep the rendered HTML flush — no whitespace between the word button and its trailing iqlab/pause/sajdah marks (otherwise RTL treats them as separate words).

## 10. Frontend behavior

### 10.1 Theming

- `tokens.css` defines `:root` and `[data-theme="light"]` (same values), plus `[data-theme="dark"]`.
- `html { scrollbar-gutter: stable }` reserves scrollbar space so `overflow: hidden` doesn't shift layout when the modal opens.
- `html.modal-open { overflow: hidden }` + `body.modal-open { overflow: hidden }` (belt-and-braces) freeze background scroll while a `<dialog>` is open.
- Theme persists via `localStorage["qr.theme"]`; an inline `<script>` in `<head>` reads it before paint to prevent flash-of-wrong-theme.
- System preference (`prefers-color-scheme: dark`) is the default when no explicit choice has been made.
- `prefers-reduced-motion: reduce` disables transitions and animations globally.

### 10.2 Surah local search

[`surah-header.js`](backend/static/js/surah-header.js) handles the local search input in the surah header:
- The input is 14px tall (font-size: var(--fs-sm)) with max-height: 60px.
- On submit, scans all ayahs in the current surah for the first one whose text contains the query (case-insensitive).
- Scrolls to that ayah with smooth behavior, applies `.ayah-focus` class, removes it after 2.5 s, and updates the URL hash so the result is shareable.
- If no match, applies `.is-error` border (red) and refocuses the input.

### 10.3 Word tooltip positioning

[`word-tooltip.js`](backend/static/js/word-tooltip.js):
- Fixed-position tooltip, positioned via JS reading `getBoundingClientRect()` of both the word and the tooltip.
- Centers horizontally on the word; flips vertically (above → below) if there isn't room above.
- Clamps to viewport edges.
- Hides on scroll, mouseleave, focusout, Escape.
- Caches responses in-memory so repeated hovers on the same word don't re-fetch.

### 10.4 Modal behavior

[`word-modal.js`](backend/static/js/word-modal.js):
- Click on a `.word` button opens the `<dialog>` via `modal.showModal()`.
- Focus is trapped inside the modal (Tab cycles through focusable children).
- Body scroll is locked via `lockBodyScroll()` which adds `modal-open` class to `<html>`. The `scrollbar-gutter: stable` rule means toggling `overflow: hidden` doesn't shift the layout horizontally.
- Refcounted lock (`scrollLockCount++` / `--scrollLockCount`) so future nested modals can't desync.
- Closes on: × button click, backdrop click, Escape (native `cancel` event).
- Focus is restored to the originally-clicked word button when the modal closes.

## 13. Performance summary

(See [`docs/research/integration-report.md`](docs/research/integration-report.md) for the full numbers.)

| Phase | RSS | HeapAlloc |
|---|---|---|
| Just-loaded, idle | ~115 MB | ~78 MB |
| Under concurrent load | ~120 MB | ~80 MB |

The heap stays under the 80 MB target. RSS exceeds it because
Go's runtime stacks + GC metadata add ~35 MB on top of the heap.
Three paths to reduce RSS further (columnar storage, mmap, lazy
loading) are documented in the integration report but out of
scope for this iteration.

## 14. Rebuilding from scratch

# Delete processed data.
rm -rf data/processed/*.gob data/processed/meta.json

# Reprocess.
go run ./pipeline/cmd/build \
  -data   ./data \
